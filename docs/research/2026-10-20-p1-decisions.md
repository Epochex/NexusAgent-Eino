# P0/P1 实施裁决与独立审查

日期：2026-10-20。用户批准设计与首阶段计划，选择原生执行；在专用 checkout/feature branch 实施，不修改简历仓库。以下为执行期间的实质裁决，按决策顺序记录。未完成项不构成生产验收。

| 裁决 | 理由及代价 |
| --- | --- |
| 使用专用 clone 和 feature branch | 隔离简历工作区并保留上游完整历史；增加一个本地 checkout。 |
| Eino StreamReader 使用过滤掉的内部 100ms probe | 锁定版本没有关闭回调，需要感知消费者 Close；每活跃模型流增加 ticker 和取消 watcher，P4 测量成本。 |
| 每次工具调用刷新权威定义 | 阻止长运行继续使用已撤销/变危险/变更 Schema 的工具；每次调用多一次有界元数据查询。 |
| 增加 1MiB Agent 输出及 4MiB 模型 SSE 总量上限 | 单帧/工具限制不能约束累计内存；超过上限的正常大输出也会被拒绝。 |
| 单步最多 32 个工具调用，并发默认 4 个 | 同时约束 Eino fanout 数量和实际调用数；大批任务需要分步，不能无限展开。 |
| 修正取消测试桩，先 flush headers 再等待 | 原桩让 HTTP/1 清理等待未完成请求状态；生产终态断言原已通过，不把测试桩问题伪装成生产修复。 |
| Host 路由也覆盖整次运行期限 | 路由发生在子 Runner 之前，仅子 Runner 期限无法覆盖；慢路由会在总期限结束时失败。 |
| 无旧 Runner 搜索命中视为预期 | rg 的退出码 1 表示零命中，不误作构建失败；不替代真实构建测试。 |
| Windows 使用 250ms SSE comment 心跳 | Hertz connstate 在 Windows 不支持远端关闭；增加少量开发环境流量，Linux 为 15 秒心跳和原生感知。 |
| 保留持久 trace 的旧数组形状 | 避免破坏既有前端；P1 run_id/seq 不是持久事件索引，恢复/重放归 P2。 |
| TraceCollector 使用稳定步骤指针和快照深拷贝 | 原切片扩容导致完成状态丢失；增加步骤对象和快照复制开销。 |
| 对默认模型配置作请求内拷贝 | DB 读取失败时共享缓存曾被采样参数修改；增加小对象复制，避免并发串用配置。 |
| CLI 保存 session ID，error/缺终态返回失败 | 原客户端丢会话且可误报成功；原来依赖截断也返回成功的调用将收到错误。 |
| 额度队列超时不计供应商熔断失败 | 未实际请求供应商不能污染健康样本；队列拥塞仍需通过本地指标判断。 |
| 工具 trace 在调用前创建 | 原逻辑漏算执行耗时；轨迹时间现在包含实际工具执行。 |
| 初始 Linux race 构建作废后重跑 | 运行时源码发生变化，结果不能归属于固定版本；付出一次完整重跑。 |
| 最终空回答判为模型错误 | 计划 Task5 与 Review Focus 冲突，采用成功必须有最终可呈现文本的语义；空白及 reasoning-only 的 stop 返回 50001，不能冒充迭代耗尽。 |
| SSE body 持有生命周期并设每 chunk 2s 写期限 | 真 TCP 停读可阻塞 Pipe/Flush；超时断开慢读客户端，正常模型停顿不受该写期限限制。 |
| server 固定 standard transport | 与 Windows/Linux 真实网络回归一致，避免跨 transport 取消/期限语义推断；其他 transport 的性能比较留到 P4。 |

独立审查范围 `4a9e6b8..13b86bc`：确认 2 项 Important，无确认 Critical/Minor。两项均通过失败回归后修复，并重新验证全包、真实网络与真实 PostgreSQL。审查者没有独立重跑 PG/Linux race；这些由实施者在修复后执行，不冒充审查者证据。没有进行第二轮代理审查。

审查未作判断的范围，实施者裁决如下：

- YAML 工作流持久审批/checkpoint/outbox/恢复/重放属于 P2；旧执行器仍在，因此整个平台不能宣称具备统一持久审批，错误使用的代价是副作用恢复不可靠。
- RAG、长期记忆、MCP、A2A 完整闭环及原有工具的平台级安全边界属于 P3；本阶段只完成迁移构建兼容，错误扩大结论会漏掉旧模块故障或越权。
- 多 worker 共享额度、全局容量与长期压力属于 P4；短微基准只描述执行内核，错误外推会高估吞吐并低估长时间资源增长。
- 原有 RAG/记忆准备调用的无 deadline 行为未在本分支引入，留在后续全链路治理；直到治理完成，这些准备阶段不能获得本次 Agent 内核的完整期限保证。

本阶段没有待处理的已确认 Critical/Important，也没有另列的 deferred minor。没有真实模型密钥，没有把模型桩、CLI HTTP 协议测试或前端构建通过写成完整平台在线业务验收。
