# P4 容量、可靠性与发布验收（2026-10-21）

验收以真实 API、Eino ADK/Graph、独立 Worker、PostgreSQL、Redis 和官方 MCP SDK 运行，模型与工具由受控 HTTP 服务提供。**200 SSE / 32 共享槽位 / 10 新请求每秒的 30 分钟基准通过：18000 次实际写出、18000 次数据库成功终态，零拒绝、零丢失 Chat 终态、零 SSE 错误、零模型/工具调用次数核对差异。**这证明当前配置的工程机制与容量，不代表真实模型回答质量、成本或线上 SLA。

## 工作负载与测量方法

- 80% 持久工作流：250ms 模型 → 100ms 只读 MCP 工具 → 250ms 模型；20% 实际 Eino ADK Function Calling → MCP → 最终答案 SSE。16 个真实用户、每用户 4 个共享运行额度；等待审批不占执行槽。
- 开放到达率：预定时间与实际 HTTP 写出分别记录，`httptrace.WroteRequest` 统计每秒 wire 请求，单独标记迟于窗口的写出。数据库独立按测试命名空间核对接收数与最终状态；受控 peer 按 nonce 核对每个成功运行 2 次模型、1 次工具。
- 36 个档位各 30 秒：50/200/500 条 SSE × 8/32/64 槽位 × 1/5/10/20 新请求/秒。SSE 包含等待审批、执行订阅和 Chat，重连间隙如实计入采样。槽位是配置上限，并非每个档位都占满。
- 另运行 30 分钟基准与 5 分钟排空；后续两次恢复周期各 5 分钟负载与 5 分钟排空。**三次排空均为 5 分钟，只有首次负载为 30 分钟**。
- API 与 Worker 各硬限制 2 CPU / 4GiB、GOMAXPROCS=2；PG 连接池各 32/12。基准应用二进制冻结于 `d8925c0`，哈希见各 manifest。之后的代码执行审计修复只影响本负载中关闭的可选沙箱；59da984 补齐过期领取时的操作收尾和发布镜像资源。本报告保留 d8925c0 实测版本，不将后续二进制冒充被测对象；正常负载不进入该过期分支。负载发生器改动单独记录。

## 故障与完整性

Worker-kill 实验在 200 SSE / 32 槽 / 10 rps 的 60 秒负载中，于测量开始 10 秒后 SIGKILL 唯一 Worker，停机 5 秒后重启。600 次实际 wire 中 6 次 Chat 显式拒绝，接收的 480 个工作流与 114 个 Chat 全部成功；无无效结果、重复 Chat nonce、未确认工作流或 SSE 错误。工作流端到端 p99 15.529 秒，恢复不是即时的。5 个运行的模型/工具次数超过干净负载的 2+1，说明只读步骤按租约恢复发生至少一次调用；不承诺外部 exactly-once。原始 `passed=false` 保留，原因是拒绝与额外调用，不能把故障恢复结论改成干净容量达标。见[完整故障报告](p4-capacity/faults/summary.json)。

- 实际两 Worker 竞争、杀进程与租约过期恢复：18 个运行全部成功，全局最多 4/每用户最多 2；等待与过期执行者围栏见[共享额度验收](2026-10-20-p4-shared-admission-validation.md)。
- Redis 故障、PG 提交失败、未知写操作、事件断线/重放与 cursor 过期：真实基础设施/进程测试覆盖，成功以 PG 实际提交为准，详见 P2/P3 报告。
- 慢 TCP 读者：真实连接的小读写缓冲与大模型输出验证停止读取后连接限时关闭、模型取消；空闲 SSE 数量测试不代替这个测试。
- PDF 恶意压缩输入触发独立容器中的解析子进程 OOM，父服务及业务后端仍存活，随后正常 PDF 可用；代码执行的非 root、网络关闭、资源限制、超时/OOM、Python/shell/Go 与真实审计另行验收，见[隔离证据](2026-10-20-p4-runtime-hardening.md)。
- 迁移 013 实际 13→12→13 保留运营政策、租约、运行和公平数据；不扩大为其它迁移 down 安全的结论，见[发布手册](deployment-runbook.md)。

真实模型尚未配置；回答质量、真实 embedding 质量、token/费用及供应商容量未验收。可选代码执行的生产 TLS 专用节点、跨机网络与备份恢复运维仍由部署环境验证。没有宣称远端写操作 exactly-once 或网络断开即可撤销。
