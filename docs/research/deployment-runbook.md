# 发布、回滚和验收

本仓库提供经测试的执行与数据机制，不将开发 Compose 等同生产集群或 SLA。容量测试中的 API/Worker 合计限制为 4 CPU/8GiB，基础设施是同一 Docker Desktop VM 中另外计费/计量的容器，不能据此推断真实跨机网络与磁盘性能。

## 发布前

1. 记录源代码 SHA、镜像 digest、Go/Eino 版本、当前数据库迁移版本。保留此前经过测试、兼容相同 Eino checkpoint 和共享额度协议的 P4 二进制。
2. 备份 PG 与引用到的 MinIO 文档对象，并在私有渠道备份 AES 主密钥。向量可按 PG 事实/文档版本重建，但不能用向量快照替代源数据备份。恢复演练先在隔离环境进行。
3. 准备独立的 JWT/AES 密钥、实际模型配置、数据库及对象存储凭据。所有 API/Worker 使用相同的持久加密配置。不要在升级时直接替换 AES 主密钥，否则既有快照将无法解密。
4. 生产基础设施须单独配置认证、TLS、备份和资源限额。`docker-compose.yaml` 的公开开发密码/端口及 acceptance Compose 的 trust/public test credentials 只用于开发验收。
5. PDF 解析部署为私有、非 root、只读、无宿主数据或 Docker socket 的独立服务。代码执行默认关闭；启用须按独立沙箱手册部署专用 TLS Docker 节点，不与主服务宿主共享控制权限。

## 升级

- 先阻止新的 Chat/工作流提交，让现有工作收尾；保留查询、取消、审批与人工核对的操作通道。不得清空 waiting_approval/needs_attention 来制造排空成功。
- 完整停止不兼容的旧 worker，再执行 `backend` 下的 `go run ./cmd/migrate`。迁移失败时保留错误并核对版本/dirty 标记，不用 force 跳过未知失败。应用启动不运行 AutoMigrate。
- 当前运行路径要求迁移到 013；PG 共享额度是权威。P3 及更早不理解这些额度的旧进程不能与 P4 混跑。不能只增加副本数、让每个进程独立计算总体限额。
- 先启动新 worker，再恢复 API 流量。检查实际 PG 容量快照、通知积压、运行状态、关键工具权限和一个完整短工作流；仅 `/healthz` 不能证明业务依赖或真实模型可用。
- 保持相同 Eino 版本和 graph schema。新进程按发布快照恢复既有 checkpoint；不支持的版本进入 needs_attention，不能自动从头重跑。
- 容器使用固定 builder 与非 root scratch runtime，包含 CA 和时区数据。API/Worker 的 `data/files` 需要同一份持久业务存储和明确权限；只读根文件系统模式下为该目录单独提供可写卷，不能将它和任意宿主目录混用。

## 回滚

优先回滚兼容的应用镜像并保留新增数据库状态。回滚前再次停止新提交与不兼容领取者，保存未知外部操作的核对证据。

013 的 down 有意保留政策、租约、共享 VIEW、索引与公平领取数据。实际 golang-migrate 演练执行了 13→12→13，比较了完整政策版本、活跃 Chat/工作流租约、运行记录与公平数据，确认未改动，并继续识别两个活跃槽。重新 up 是幂等 DDL，不覆盖运营者设置的政策。

这只证明迁移 013 的兼容回退；不授权连续 down 其它数据迁移，也不能据此启动不理解共享额度的旧 P3 进程。不要删 checkpoint、请求键、未知写操作或加密凭据来恢复表面可用性。

## 故障核对

- Redis 不可用：PG 运行与事务 outbox 保留，通知可恢复后补发；检查 unpublished 行是否排空。投递是至少一次，消费者以稳定运行/序号识别重复。
- PG 不可用：不能提交成功。Chat 成功消息及运行终态必须以实际事务为准；错误/未知状态要暴露，不能用 HTTP 200 或已有临时文本代替成功证据。
- Worker 被杀：租约过期后恢复可重试节点；未知非幂等写入进入人工核对。即使 HTTP 已取消，也不能假定远端未执行。
- SSE 断开：订阅不拥有工作流的执行生命周期。客户端用事件序号重连；过期 cursor 返回 410 并要求读取快照。Chat 慢读者触发有界写入/取消，实际 TCP 端到端测试独立于空闲 SSE 数量测试。
- A2A：同一 request_key 不重复发送未知委派。每用户 10000 条是当前总历史硬上限，达到后需管理员处理；没有自助归档接口，不能删去重键来重新发起同一业务。

## 实际验收分层

CI 验证 Go vet/race、真实 PG/Redis/MinIO/Milvus、实际 server/worker 进程、PDF 解析容器故障和前端构建。独立原生 Docker 控制测试验证代码沙箱，未显式配置镜像时会跳过，不能将 skip 算作已测。

容量报告给出每个档位的实际 wire 到达、拒绝、接收、数据库最终状态、MCP/模型调用次数、控制接口分位数、CPU/堆/GC/连接与积压，并保留未达标档位。30 分钟基准和三次排空观察有各自真实时长。

真实模型服务尚未配置。其回答质量、真实 token/费用、外部供应商吞吐、跨机网络和实际线上 SLA 均不在受控模型验收结论中。
